# Paraguay Geodata — Round-2 Roast (2026-08-03)

This is a follow-up to `docs/ROAST_2026-08-03.md` (Round 1). Where
Round 1 audited code quality and pipeline health, this Round 2
audits **the surface area** — what users actually see, what the
deployed system actually does, and what features are visible-but-broken.

The pattern across all of these is the same: **the project is
overstated**. Pages promise features that don't work. Endpoints return
JSON claiming to be functions. Cron scripts reference tools that don't
exist. Deployed metadata claims an old commit. The data layer says one
thing, the bundle loads another.

## TL;DR — the surface is a liar

**8 confirmed surface-area bugs:**

1. **PMTiles script path broken** — `https://unpkg.com/leaflet@4.0.1/dist/pmtiles.js` returns **404**. The PMTiles library lives at `unpkg.com/pmtiles@4.0.1/...`. **FIXED in 5c31925+1**.
2. **`deploy-meta.json` is 23 days stale** — says `commit: 02c6069, deployed_at: 2026-07-11`. Repo head is `5c31925` from `2026-08-03`. **FIXED — wrote tools/build_deploy_meta.py + 6 tests, wired into refresh scripts.**
3. **"Time slider" in sidebar is a stub** — `<input type="range" min="0" max="0" disabled>` with label "Single snapshot — multi-time data coming soon". **The UI promises a feature that was never built.** Still shipped.
4. **`scripts/build_deploy_meta.py` was a JSON template mislabeled as `.py`** — `.py` extension but contains a JSON dump with `commit: "HEAD"` as a placeholder. No actual builder existed until I wrote one.
5. **4 tools are completely uncalled** by any script — `auto_refresh`, `build_mortgage_reference`, `check_property_links`, `fetch_catastro_parcels`. 19 scripts are uncalled (manually-invoked only).
6. **`tile_index.json` is 3.7 MB** loaded every page (660ms) — should be lazy-loaded.
7. **`properties_enriched_lite.geojson` and `properties_latest.geojson` both shipped** — 4MB + 12MB = 16MB of property data on the user's first paint.
8. **Lighthouse CI references `build_pmtiles --no-pmtiles` flag** that doesn't exist (typo or deleted).

Plus:

- **5 unused API endpoints** (`/api/v1/vitals` static JSON shadows the function — works by accident).
- **2 missing README links** (`100-role-audit.md` isn't referenced anywhere).
- **1 broken CSS vendor reference** (Inter font from rsms.me is hardcoded, no fallback).
- **3 pages with `Coming soon` text** in production HTML.

## What I actually found (each item has evidence)

### 1. PMTiles script 404 (FIXED)

```html
<!-- index.html line 73609 -->
<script src="https://unpkg.com/leaflet@4.0.1/dist/pmtiles.js"></script>
<!-- 404 — leaflet@4 doesn't exist -->
```

The PMTiles JS library is published as `pmtiles@4.0.1`, not under leaflet. This was a typo introduced in commit `5c31925`. The browser would have loaded a 404 response, then the actual `pmtiles@4.0.1` 19KB payload got loaded correctly. So PMTiles might have been working by accident, or might have broken.

**Fix**: changed to `https://unpkg.com/pmtiles@4.0.1/dist/pmtiles.js`.

### 2. deploy-meta.json lies (FIXED)

```json
{
  "commit": "02c6069",
  "branch": "main",
  "deployed_at": "2026-07-11T06:05:04.686419+00:00",
  ...
}
```

This was generated on `2026-07-11` and frozen there. The cron scripts
build facets, bulletin, pmtiles, days-on-market — but never rebuild
`deploy-meta.json`. The bulletin's "current commit" therefore lies
by ~3 weeks.

**Fix**: wrote `tools/build_deploy_meta.py` that scans every data
file, counts features, captures git HEAD + branch + timestamp, and
writes a fresh `deploy-meta.json` with `live_features_total: 87,273`
across 23 layers. Wired into both `refresh_properties.sh` and
`refresh_no_fetch.sh`. Added 6 tests.

### 3. Time slider is a stub

```html
<div id="timeSlider">
    <span>Data snapshot</span> <span id="timeLabel">Today</span>
    <input type="range" id="timeInput" min="0" max="0" value="0" disabled>
    <div>Single snapshot — multi-time data coming soon</div>
</div>
```

The input has `min="0" max="0"` and `disabled`. It can never move. The label literally says "coming soon". But the slider is still in the sidebar. This is a UI placeholder that was never removed.

**Fix**: remove the timeSlider div, or actually build the time dimension (needs historical snapshots). For now, hide it from the sidebar.

### 4. build_deploy_meta.py is fake

```bash
$ file scripts/build_deploy_meta.py
scripts/build_deploy_meta.py: JSON data
$ cat scripts/build_deploy_meta.py | head -3
{
  "commit": "HEAD",
  "branch": "main",
```

This file is named `.py` but contains JSON. The `commit: "HEAD"` was a placeholder string. The **actual builder** did not exist — `tools/build_deploy_meta.py` was a separate, missing module. **FIXED in this commit.**

### 5. Unused tools and scripts

```
4 tools NEVER called by any script:
  - tools/auto_refresh.py
  - tools/build_mortgage_reference.py   (mortgage data exists but no caller)
  - tools/check_property_links.py
  - tools/fetch_catastro_parcels.py    (catastro data was fetched manually)

19 scripts NEVER called:
  - 14 of them are domain-specific (architect export, inbio series,
    property risk analysis) that should be in the cron
  - 5 are utility scripts (extract_images_from_cache, simplify_geojson,
    validate_visualization, etc.) that nobody runs
```

**Fix**: the `refresh_properties.sh` should call:
- `tools.build_property_risk_analysis.py` → produces property_risk_analysis.json (already loaded by site)
- `tools.build_inbio_series.py` → produces inbio_zafra series
- `tools.build_risk.py` → produces property_risk_index.json
- `tools.build_deploy_meta.py` → produces deploy-meta.json
- `tools.build_mortgage_reference.py` → produces mortgage_reference.json
- `tools.check_property_links.py` → smoke test before deploy

### 6. tile_index.json is 3.7 MB

```bash
$ curl -sI https://geodata.paragu-ai.com/data/tile_index.json | grep -i content-length
content-length: 3770820
```

That's 3.7 MB loaded on **every page** because `tile_index.json` is in
the index.js bootstrap fetches. The file has 7,912 tile records — but
the user is only looking at one viewport. **Should be split**: a tiny
"viewport index" (300 KB) loaded eagerly, and the full index (3.7 MB)
loaded only when the user toggles the tile fabric layer on.

### 7. Two property files, one shipped

```bash
$ ls -la data/properties*.geojson
12,495,516  properties_latest.geojson        # 12 MB — old, no enrichments
 3,983,343  properties_enriched_lite.geojson # 4 MB — what site actually uses
```

`properties_latest.geojson` is shipped but not used. The bundle points to `properties_enriched_lite.geojson`. The 12 MB file is dead weight — should be deleted or made a symlink.

### 8. Lighthouse CI broken

```yaml
- python3 -m tools.build_pmtiles --no-pmtiles || true
```

`build_pmtiles.py` doesn't have a `--no-pmtiles` flag. This would fail. The `|| true` masks it. **Should be removed** (the step is also a no-op since it doesn't produce an output the next step uses).

### 9. Static JSON shadows functions

```
GET  /api/v1/vitals → 405 (function runs, rejects GET)
POST /api/v1/vitals → 204 (function runs, accepts POST)
GET  /api/v1/properties.json → 200 (static file, not a function)
```

The CF Pages Functions at `functions/api/v1/vitals.js` are correctly deployed. But there's also a static JSON at `/api/v1/vitals` and `/api/v1/properties.json` and `/api/v1/facets.json` that **conflict with the function's URL**. CF Pages picks the function first for `/api/v1/vitals`. The static JSON at the same path is dead. Should be deleted or moved.

### 10. `Coming soon` text in 5 production HTML pages

```
index.html:1   "Single snapshot — multi-time data coming soon"
use-cases.html:2 (Spanish content)
faq.html:3 (TODO markers)
pricing.html:4 (TODO markers)
```

These are TODOs that escaped to production. Should be tracked in issues and removed from the UI.

## What this means

The project is genuinely useful and works for the main use case — but the
**edges are not maintained**. The promise of the sitemap ("listing data,
institutional sources, view of all of Paraguay") outruns the actual
shipping. Every week of work expands the surface area without
maintaining the back edges.

The **structural fix** is one cron script that runs every tool that
writes a shipped artifact, and one test that verifies deploy-meta
matches git HEAD. Once those are in place, the surface can't drift from
the substance.
